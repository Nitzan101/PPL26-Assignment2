Q1.7: A Lexical Address is a way for the computer to find a variable's value without actually using its name. it's represented as a pair (i,j), while i describes how many levels "out" it needs to look, and j is the position of the variable. For example:

```ts
(lambda (x y)
    (lambda (x z)

    )    
)
```
x -> (0,0)
y -> (1,1)

Q1.9: a. Performance: Avoiding redundant calculations of unused arguments.

Error Handling: Avoiding runtime errors (e.g., division by zero) in unused branches.

Termination: Handling infinite loops that appear in unused arguments. 

Example:

```ts
(
 (lambda (x y z)
    (if (> x 5)
        y
        (if (> x 2)
            z
            x
        )
    )
 )
 1
(+ y 6)
 (/ z 0)
)
```

In this example, if we'll use applicative order we will calculate x,y,z, while with normal we would calculate only x, and the program will also get a runtime error due to division by zero.

b. The primary justification is to improve Performance by avoiding redundant evaluations. In Normal Order, if a parameter appears multiple times in the function body, the expression is re-evaluated for every occurrence. Applicative Order evaluates the argument only once before passing it, which saves time for expensive calculations.

Note: Whether AO or NO is faster depends entirely on the program's structure. AO is more efficient when arguments are used multiple times, whereas NO is more efficient when arguments are not used at all.

Example:

```ts
(
 (lambda (x) (+ x x x x x))
 (sqrt 488)
)
```

In Normal Order: The (sqrt 488) is substituted 5 times: 
(+ (sqrt 488) (sqrt 488) (sqrt 488) (sqrt 488) (sqrt 488)).

In Applicative Order: The (sqrt 488) is evaluated first, and its result is reused: (+ <result> <result> <result> <result>  <result>).

Q1.10: a. In the Substitution Model, this function converts a runtime Value back into a CExp (a part of the AST).

Why we need it:
When we evaluate a function call, we first calculate the arguments, which gives us Values (like the number 5 or a Closure). However, the substitute function only knows how to work with code structures (CExps). It cannot take a "live" value from the computer's memory and just paste it into the source code of the function's body.

Because substitute expects a CExp as an input, we use valueToLitExp to wrap the value back into a format that the AST understands (like a NumExp or LitExp).

b. The valueToLitExp function is not needed in the normal evaluation strategy interpreter because in Normal Order evaluation, we do not evaluate the operands before applying the function. Instead, we pass the arguments as they are—original expressions (CExps)—directly into the function body.

Since the substitute function already expects a CExp as an input, and in Normal Order we haven't converted these expressions into Values yet, there is no need for a conversion function like valueToLitExp.
